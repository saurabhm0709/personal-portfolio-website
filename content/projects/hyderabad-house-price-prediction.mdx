## Overview

The goal of this project is to predict the listed price of residential properties in Hyderabad from the attributes in a listing (size, configuration, locality and similar fields). It covers the full workflow, from collecting raw listings to deploying a model, with most of the effort going into the parts that usually decide whether a model can be trusted: data quality, feature design and evaluation.

Before choosing an imputation strategy, I looked at _how_ values were missing, not just how many. If a field is missing more often for certain localities or property types, dropping those rows biases the dataset, and a naive imputation hides the pattern.

### Train/test splitting by property group

A random row-level split is misleading here. If near-identical listings of the same property land in both the training and test sets, the model is effectively tested on data it has already seen, and the test score overstates real performance. Splitting by **property group** keeps every listing of a property on the same side of the split, so the test set measures generalisation to properties the model has never seen.

<Callout title="Why this matters">
  Leakage of this kind doesn't cause an error. It produces a better-looking number. The only defence is
  to define the split around how the model will actually be used.
</Callout>
